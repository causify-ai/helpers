- This file contains conventions for C4 diagrams (Context, Container, Component,
  Code)

# Diagram Language

## Always Draw C4 Diagrams With PlantUML

- Draw every C4 diagram with PlantUML and the C4-PlantUML library, in a
  `plantuml` code fence
- Never draw a C4 diagram with Mermaid (`C4Context`, `C4Container`,
  `C4Component`)
  - Mermaid places C4 shapes on a fixed grid whose row width is capped at the
    screen width of the headless browser (800 px)
  - Shapes with long descriptions are about 300 px wide, so two of them plus
    the margins do not fit in a row
  - Each shape gets its own row and the diagram renders as one long column
  - PlantUML lays out the shapes from the relations, so the layers and the
    neighbors of a system stay close
- Mermaid is still valid for diagrams that are not C4 (e.g., mind maps), see
  `.claude/skills/figure.rules.md`
- Render the diagram with `render_images.py`, which handles the `plantuml` fence

## Start Every Diagram With the Same Header

- Write the three header lines in this order
  ```plantuml
  !pragma layout smetana
  !include <C4/C4_Container>
  LAYOUT_TOP_DOWN()
  ```
- Do not write `@startuml` and `@enduml`: `render_images.py` adds them
- Keep `!pragma layout smetana`
  - The PlantUML Docker image has no Graphviz
  - Without the pragma the render fails with "Cannot find Graphviz"
- Include the C4 library with `!include <C4/C4_...>`, not with a URL
  - The library is bundled in `plantuml.jar`, so the include works offline
  - Use `<C4/C4_Context>`, `<C4/C4_Container>`, or `<C4/C4_Component>` for the
    level of the diagram
  - Each library includes the levels above it, so `Container_Ext` is available
    in a component diagram
- Pick the direction with `LAYOUT_TOP_DOWN()` or `LAYOUT_LEFT_RIGHT()`
  - Use `LAYOUT_TOP_DOWN()` for layers and call chains
  - Use `LAYOUT_LEFT_RIGHT()` for one central system with several neighbors

# Elements and Relations

## Use the C4-PlantUML Macros

- Use these macros, which have the same names and arguments as in Mermaid
  - `Person(id, "label", "description")`
  - `System(...)` and `System_Ext(...)` for a system and an external system
  - `Container(id, "label", "technology", "description")`, `Container_Ext(...)`,
    and `ContainerDb(...)`
  - `Component(...)` and `Component_Ext(...)`
  - `Container_Boundary(id, "label") { ... }` and `System_Boundary(...)`
  - `Rel(from, to, "label", "technology")`
- Indent the elements inside a boundary by 2 spaces
- Put the C4 level in the title, e.g., `title Estimate Paper Quality: Context`

## Escape Creole Markup in Labels

- PlantUML reads `--text--` in a label as strikethrough
- Write `~-~-` for a literal `--`
  - **Bad** (renders `input, output_dir` with a line through `input,`)
    ```plantuml
    Rel(user, cli, "--input, --output_dir")
    ```
  - **Good**
    ```plantuml
    Rel(user, cli, "~-~-input, ~-~-output_dir")
    ```
- Write other label text as is: `<doi>`, `%PDF`, `lookup_*()`, and `_get()` render
  literally

# Size

## Set the Displayed Size With the Fence Bracket

- Set the width of the rendered image in the fence header, e.g.,
  `` ```plantuml[width=80%] ``

# Verification

- [ ] The diagram is in a `plantuml` fence, not a `mermaid` fence
- [ ] The header has the three lines `!pragma layout smetana`,
      `!include <C4/C4_...>`, and a `LAYOUT_*()` line
- [ ] There is no `@startuml` or `@enduml`
- [ ] No label contains `--` without the escape `~-~-`
- [ ] The rendered image has no overlapping shapes or labels
